# What to review before activation

## 1. Slow Feed judgment

- Does the synthetic feed feel genuinely quieter than an inbox or activity log?
- Does each card explain why it made the cut?
- Can every claim be traced to the right source door without exposing unnecessary private text?
- Does Now contain only genuine decisions, with Watching, Handled, and the full
  history easy to find under Activity?

## 2. Approval language

- Is it unmistakable that a proposal has not been approved or executed?
- Are provider acknowledgement, delivery, and read displayed as separate evidence?
- Does an edit invalidate the previous payload hash and revision?
- Is read-only mode the default you want for the first live source?

## 3. Agent judgment

- Do the five role prompts sound like the same quiet practice while preserving distinct jobs?
- Which single source should become the first live, dedicated test scope?
- What should never be stored, even as an excerpt?

## 4. Native feel

- Is the density calm but still operational?
- Are keyboard navigation, search, source inspection, reduced motion, increased contrast, and empty/error states acceptable?
- Should Quiet Desk be the final product name?

## 5. Activation boundary

- Decide whether the next milestone is the read-only live hub adapter in the
  Mac app or the first provider source connector; the current Mac bundle remains
  synthetic even though the hub/bridge path is functional locally.
- Choose where to host Quiet Hub and the Grok-facing MCP bridge.
- Create separate Codex and Grok connection identities and secrets.
- Review retention/deletion policy before any personal source data enters the hub.
- Do not authorize an external executor in the first live test.
